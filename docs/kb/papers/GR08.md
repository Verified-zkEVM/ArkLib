# GR08

## At A Glance

`GR08` is Guruswami–Rudra, *Explicit Codes Achieving List Decoding Capacity: Error-Correction
With Optimal Redundancy*, IEEE Transactions on Information Theory **54**(1) (2008) 135–150 — the
paper that introduced **folded Reed–Solomon codes** and showed they achieve list-decoding
capacity.

ArkLib uses it as the definitional source for folded Reed–Solomon: `ABF26` Definition 2.15 is a
restatement of GR08 Definition 2.1, and `ReedSolomon.Folded.frsCode` transcribes it.

## What ArkLib Uses From This Paper

- **Definition 2.1 (folded Reed–Solomon).** *"the codewords of `FRS_{F,γ,m,k}` are in one-one
  correspondence with those of the RS code `C` and are obtained by bundling together consecutive
  `m`-tuples of symbols in codewords of `C`."* Evaluation points `1, γ, …, γ^{n−1}` are all
  distinct, the folded domain is `{γ^{jm}}`, and the fold is by multiplication `x ↦ γⁱ·x`.
  Formalized as `ReedSolomon.Folded.frsCode` / `frsEvalOnPoints`.
- The **injectivity setup** implicit in that definition — that the `n·s` folded evaluation points
  `domain x · ωʲ` are pairwise distinct — which is what ArkLib's
  `ReedSolomon.Folded.Admissible` and `admissible_foldedPoints_injective` capture.
- Nothing algorithmic. GR08's list-decoding algorithm and its capacity theorem are not
  formalized; ArkLib proves the code's encoder injectivity in the nonsaturated range, exact
  saturated dimension, and minimum distance.

## Version Notes

- Notation map: GR08 `γ` ↦ ArkLib `ω` (the fold multiplier), GR08 `m` ↦ ArkLib `s` (the fold
  arity), GR08's folded domain `{γ^{jm}}` ↦ ArkLib's abstract `domain : ι ↪ F`.

## Known Divergences From ArkLib

- **`ABF26` Definition 2.14's admissibility is strictly weaker than the injectivity GR08's
  results need, and ArkLib strengthens it.** As printed, ABF26 D2.14 quantifies over
  `binom(L,2)` — *distinct* pairs — so nothing constrains `α` against itself and `ω = 1` is
  admissible for every `L` and every `s`. `ReedSolomon.Folded.Admissible` adds the intra-orbit
  clause `α · ωⁱ ≠ α` for `0 < i < s`; together with the printed inter-orbit clause (and
  `ω ≠ 0`) this is exactly injectivity of `(α, i) ↦ α · ωⁱ` on `L × Fin s`, which is GR08's own
  setup.
  **The strengthening is necessary, not merely defensible.** Exhaustive brute force over all
  message polynomials in `(ZMod 11)^k`, with `L` the quadratic-residue subgroup, `s = 2` and
  `ω = 1` (a value the literal D2.14 permits), gives true minimum distances `5, 4, 3, 2, 1` for
  `k = 1..5` against the folded-RS formula's `5, 5, 4, 4, 3` — i.e. under D2.14 as printed the
  GR08/ABF26 distance claim is false. The strengthening appears in **hypothesis position only**,
  so every ArkLib FRS theorem is weaker than ABF26's printed claim, never stronger.
- **`frsCode` is the plain Reed–Solomon code on the folded domain** — GR08 Definition 2.1's own
  "one-one correspondence with the RS code" framing. Concretely,
  `frsCode domain k s ω = (ReedSolomon.code foldedDomain k).map (LinearEquiv.curry …)` where
  `foldedDomain : ι × Fin s ↪ F` is `(x, j) ↦ domain x · ωʲ`. This is now stated as
  `frsCode_eq_map_rsCode`, with injectivity supplied by `admissible_foldedPoints_injective`.
  ArkLib transports the RS dimension theorem through that bridge to obtain the exact saturation
  formula `dim_frsCode_eq_min`; `dim_frsCode` is its full-dimension corollary. Minimum distance
  genuinely cannot be transported this way, because the FRS metric is the *block* Hamming metric
  on `ι → (Fin s → F)`, not the symbol metric on the folded domain.
- **The fold is `x ↦ ωʲ·x`, not `x ↦ x^{qʲ}`.** The Frobenius/algebraic-geometric variant is a
  different construction; neither GR08 nor ABF26 uses it here.
- **Not the FRI fold.** `ArkLib/Data/CodingTheory/ProximityGap/Folding.lean` (and
  `Data/Polynomial/SplitFold`, `FoldingPolynomial`) implement FRI split-and-fold, which *shrinks*
  the evaluation domain and *drops* the degree bound — the opposite construction to GR08's, where
  the degree bound is unchanged and the alphabet grows. The disambiguation paragraph in
  `Folded.lean` is accurate and worth preserving.
- **"MDS" needs a caveat.** ArkLib proves `minDist = |ι| − ⌊(k−1)/s⌋`, equal to
  `n − ⌈k/s⌉ + 1`. Under ABF26's own MDS definition (`ρ(C) = 1 − δ_min(C) + 1/n` with
  `ρ = k/(s·n)`) the code is MDS exactly when `s ∣ k`; it always meets the *integer* Singleton
  bound `d ≤ n − ⌈log_{|Σ|}|C|⌉ + 1`.
- **GR08 uses a more specialized domain than ArkLib.** GR08 Definition 2.1 takes the
  generator-ordered nonzero points `1, γ, …` and bundles consecutive powers. ABF26 and ArkLib
  generalize this to an arbitrary injected domain whose folded orbits satisfy `Admissible`.
  ABF26's smoothness condition (Definition 2.12) is orthogonal and is not part of `frsCode`.

## Open Formalization Gaps

- **GR08's headline results are absent**: the list-decoding algorithm, the capacity theorem, and
  the rate/redundancy trade-off. ArkLib has only the code, its dimension, and its distance.
- A named full-dimension rate simplification (`ρ(frsCode) = k/(s·|ι|)`) is not isolated, although
  it follows from `dim_frsCode` and the existing alphabet-rate conversion lemmas.
