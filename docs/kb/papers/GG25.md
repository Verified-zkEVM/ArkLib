# GG25

## At A Glance

`GG25` is Goyal–Guruswami, *Optimal Proximity Gaps for Subspace-Design Codes and (Random)
Reed–Solomon Codes*, ePrint 2025/2054.
It proves proximity-gap results at the optimal radius for subspace-design codes and for random
Reed–Solomon codes.

ArkLib uses its subspace-design rate bound, line-decoding interface, and explicit MCA bounds for
subspace-design and folded Reed--Solomon codes. These results are stated on ArkLib's canonical
`mcaError` carrier; the external proofs remain admitted.

## What ArkLib Uses From This Paper

- **Lemma 2.16** (= `ABF26` Lemma 2.17): *"For any `τ`-subspace-design `F_q`-additive code of
  rate `R`, we must have `τ(r) ≥ R − 1/n` for all `r ∈ ℕ`."* Formalized as
  `CodingTheory.subspaceDesign_tau_lower_of_ne_bot` and its total wrapper
  `CodingTheory.subspaceDesign_tau_lower`, proved via the module-alphabet Singleton bound
  `LinearCode.singleton_bound_module`.
- **Definition 2.15** (subspace-design code) and **Definition 2.18** / **Theorem 2.19** (the
  folded-RS subspace-design statement) as comparison points for
  `CodingTheory.IsSubspaceDesign` and `CodingTheory.isSubspaceDesign_frsCode`. GG25's proof of
  L2.16 ("pick any non-zero codeword `c`…") is also the source-shaped alternative to ArkLib's
  `hτ_nonneg` guard.
- **Definition 3.1** and **Theorem 3.5** → `CodingTheory.IsLineDecodable` and
  `CodingTheory.IsLineDecodable.mcaError_le`. The definition requires the concluding challenges
  to be both close to the ambient affine line and aligned with one affine pair of codewords.
- **Corollary 4.9** → `CodingTheory.subspace_design_mcaError_le`, the affine-line MCA bound for
  subspace-design codes.
- **Corollary 4.10** → `CodingTheory.frs_mcaError_le`, the integer-parameter capacity bound for
  admissibly folded Reed--Solomon codes.

## Known Divergences From ArkLib

- **L2.16 is stated for all `r ∈ ℕ` and is literally false at `r = 0`.** `dim A ≤ 0` forces
  `A = ⊥`, so the design inequality degenerates to `0 ≤ 0 · τ(0)` and constrains nothing; a `τ`
  with `τ(0) < R − 1/n` then refutes the claim. GG25's own proof concedes the point ("We just
  need to prove the result for `r = 1` since we can just take `A` of dimension at 1"). ArkLib
  restricts to `r ≥ 1`, which is a correction, not a weakening.
- **Range now matches GG25 L2.16 up to the `r = 0` correction.** `subspaceDesign_tau_lower`
  concludes for **all** `r ≥ 1` (given `1 ≤ s`); an earlier revision narrowed it to
  `r ∈ Finset.Icc 1 s`, which has been lifted. Two forms are shipped:
  `subspaceDesign_tau_lower_of_ne_bot` carries GG25's own argument under `C ≠ ⊥` (the
  source-shaped hypothesis), and `subspaceDesign_tau_lower` is the total wrapper that assumes
  `0 ≤ τ` instead so it can also cover the degenerate `C = ⊥` branch. Neither hypothesis is
  derivable from the other.
- **`τ`'s codomain.** GG25 constrains `τ : ℕ → ℝ_{≤1}`; ArkLib instead carries an explicit
  `hτ_nonneg : ∀ r, 0 ≤ τ r`, used only to dispatch the `C = ⊥` branch. Some guard is genuinely
  required — with `τ ≡ −1` and `n = 2` the unguarded statement is false. The `C ≠ ⊥` variant is
  the source-shaped argument implicit in GG25's proof, which begins by choosing a nonzero
  codeword; the printed theorem itself does not state that hypothesis.
- **Definition 2.18 / Theorem 2.19 omit the `ω`-order condition, and the restatement is false
  without it.** GG25 Def 2.18 asks only for `α₁, …, α_n ∈ F_q` distinct with `αᵢγᵗ ≠ αⱼ` for
  `i ≠ j`, `t < s`, and Thm 2.19 adds only `q > s·n`. This is the same omission as in `ABF26`
  Theorem 2.18, and it is falsified by the same compiled counterexample: `𝔽₁₇`, `n = 7`,
  `s = 2`, `k = 3`, `ω = −1` — note `q = 17 > s·n = 14`, so GG25's own side condition holds. The
  hypothesis that is actually needed is `GK16` Lemma 12's: `ω` must generate `F*`. ArkLib carries
  it as `hω_gen`.
- **Definition 2.18 also permits `0` as an evaluation point**, under which the theorem is false
  *even with* the order condition (compiled: `ZMod 5`, `domain = (0, 1)`, `s = 3`, `k = 2`,
  `ω = 2` a generator). ArkLib excludes it via the strengthened
  `ReedSolomon.Folded.Admissible`. Both omissions should go upstream to GG25 as well as to
  ABF26.

- The random-Reed--Solomon half of the paper has no ArkLib counterpart.
