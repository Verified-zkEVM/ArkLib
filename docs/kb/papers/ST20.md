# ST20

## At A Glance

`ST20` is Shangguan–Tamo, *Combinatorial list-decoding of Reed-Solomon codes beyond the Johnson
radius*, STOC 2020 — the source of the **generalized Singleton bound** for list decoding.

## What ArkLib Uses From This Paper

Theorem 1.2, in two halves. The alphabet-generic half is `|C| ≤ L·q^{n−a}` with
`a = ⌊(L+1)rn/L⌋`; the linear refinement, for `C ⊆ F_q^n` with `q > L`, drops the factor `L`. [ABF26]
Theorem 3.9 prints only the linear half, and adds the consequence `δ ≤ ℓ/(ℓ+1)·(1−ρ)`.

## Main ArkLib Touchpoints

`linear_card_le_generalized_singleton` in [Bounds.lean](../../../ArkLib/Data/CodingTheory/ListDecodability/Bounds.lean) is the proved implication from
list-decodability; `linear_card_le_of_rate_radius` is the proved arithmetic step from the
rate–radius relation to the cardinality bound. Both are axiom-clean.

## Known Divergences From ArkLib

**[ABF26]'s printing drops two hypotheses, and the statement is false without either.** Both are
carried in Lean.

1. *Integrality.* [ST20]'s proof opens "Let `a := ⌊(L+1)rn/L⌋ = rn + ⌊rn/L⌋` (**assuming `rn` is an
   integer**)", and the identity fails otherwise. Without it, `C = {000, 111, 222}` over `𝔽₃` at
   `δ = 1/2, ℓ = 1` is a counterexample: minimum distance `3` makes the radius-`1` balls disjoint, yet
   `⌊(ℓ+1)/ℓ·δ·n⌋ = 3` forces `|C| ≤ 3^0 = 1 < 3`. (Separately, [ST20] assume `rn/L ∈ ℤ` "for ease of
   presentation", which only removes the floor.)
2. *Non-negative exponent.* Their pigeonhole needs `a ≤ n`, there being `q^{n−a}` prefixes only then.
   Without it the zero code refutes the statement: `C = ⊥`, `n = 10`, `δ = 9/10`, `ℓ = 1` has
   `Λ = 1 ≤ ℓ` and `δ·n = 9 ∈ ℕ`, while `a = 18 > n` forces `|C| ≤ q^{−8} < 1`. The same omission voids
   [ABF26]'s "Consequently `δ ≤ ℓ/(ℓ+1)·(1−ρ)`".

Both counterexamples are compiled and axiom-clean; the ABF26 audit records their exact parameters.
The alphabet-generic half is not formalized.

## Open Formalization Gaps

The alphabet-generic first half `|C| ≤ L·q^{n−a}`. The linear implication used by [ABF26] is proved
in-tree by pigeonholing `L+1` codewords agreeing on the first `n−a` coordinates, then partitioning
the remaining `a` coordinates as evenly as possible into `L+1` blocks.
